# 説明ログ(プレゼミ生への説明用)

## 段階:テストツール vitest の導入と ERESOLVE(依存関係の衝突)の解決

### 作ったもの
- テストを実行するための道具 `vitest` を、プロジェクトに追加した。
- あわせて `@types/node` を 20 系から 24 系に更新した。
- 変更されたファイル:`package.json`、`package-lock.json`

### 使った技術
- npm(Node.js のパッケージ管理ツール)
- vitest 5.0.4(テストフレームワーク)
- @types/node 24.19.2(Node.js の型定義)

### なぜそうしたか
最初に `npm install -D vitest` を実行したところ、`ERESOLVE` というエラーで止まった。

**何がぶつかったか**

| 部品 | 求めているもの |
|---|---|
| このプロジェクト | `@types/node` は 20 系(`^20`) |
| vitest 5.0.4 | `@types/node` は 22 系、または 24 以上(`^22.0.0 \|\| >=24.0.0`) |

プロジェクトは「20 系を使う」と書いているのに、vitest は「20 系は困る」と言っている。npm は、どちらを優先するか自分では決められないので、止まってエラーを出した。

**解決方法**
1. 自分の PC の Node.js は v24.16.0 なので、型定義も同じ 24 系に揃えるのが自然だと判断した。
2. 先に `npm install -D @types/node@24` で型定義を 24 系に上げた。
3. そのあとに `npm install -D vitest` を実行した。今度は衝突せず、そのまま入った。

**やらなかったこと**
`--force` や `--legacy-peer-deps` を付ければ、エラーを無視して入れることはできる。ただし、食い違いを抱えたまま動かすことになり、あとで原因の分かりにくい不具合が出るおそれがある。そのため、食い違いそのものを直す方法を選んだ。

### 確認方法
cmd で次の 2 つを実行する。

```
npm ls vitest @types/node
npx tsc --noEmit
```

- 1 つ目:`vitest@5.0.4` と `@types/node@24.19.2` が表示され、`invalid` や `UNMET` が出ないこと。
- 2 つ目:何も表示されずに終わること(型エラーが 0 件)。

実際の結果:どちらも問題なし。

### 初出の専門用語と一言解説
- **ERESOLVE**:npm が「依存関係をどう組み合わせても、条件を満たせない」と判断したときのエラー名。
- **依存関係(dependency)**:あるパッケージが動くために必要な、別のパッケージのこと。
- **peer dependency(ピア依存)**:「このバージョンの部品と一緒に使ってね」と、パッケージが利用者側に求める条件。
- **vitest**:テストを書いて実行するための道具。順位計算が正しいかを自動で確かめるのに使う。
- **@types/node**:TypeScript に Node.js の機能を教えるための型定義。
- **devDependencies(`-D`)**:開発中だけ使い、本番では使わない部品の置き場所。
- **package-lock.json**:実際に入ったバージョンを記録するファイル。誰が入れても同じ構成になる。
- **`tsc --noEmit`**:TypeScript の型チェックだけを行い、ファイルは出力しないコマンド。

## 段階1:順位計算 `lib/ranking.ts` とテスト

### 作ったもの
- `lib/ranking.ts`:順位を計算する 2 つの関数。
  - `computeRanking(videos, votes)`:動画と票から、順位つきの一覧を作る。
  - `filterByRevealStage(ranking, stage)`:発表段階(0〜3)で見せてよい順位だけを取り出す。
- `lib/ranking.test.ts`:上の関数が正しいかを確かめる自動テスト 20 件。
- `vitest.config.mts`:テストの設定(`lib/` 内の `*.test.ts` を対象にする)。
- `package.json` に `test` スクリプトを追加(`npm test` でテストを実行)。

### 使った技術
- TypeScript(型つきの JavaScript)
- Vitest(テストツール)

### なぜそうしたか
- **純粋関数にした**:DB も画面も使わず、「入力を渡せば結果が返る」だけの形にした。DB がなくても、テストだけで正しさを確かめられるため。
- **最初に作った**:この関数がシステムの核心(ルールそのもの)で、ほかの部分はこれを呼ぶだけになるため。
- **平均の比較は割り算せず、整数で比べた**:`1/3` のような割り切れない平均は、小数にすると誤差が出て「同点のはずが同点にならない」ことがある。合計と件数の整数どうしを掛け算で比べれば、誤差が出ない。
- **同順位は標準競技順位(1,2,2,4)**:同順位が 2 人いたら、次は 3 位ではなく 4 位にする。
- **段階の絞り込みも関数にした**:見せてはいけない順位を「画面で隠す」のではなく、「関数が返さない」ようにするため。API はこの関数の結果をそのまま返せばよい。
- **3 位が存在しない場合**:該当者のいない順位は、空の一覧を持つ順位として返す。画面側が「該当者なし(同順位のため3位はいません)」と表示する。

### 確認方法
cmd で次を実行する。

```
npm test
```

`Tests 20 passed (20)` と表示されれば成功。型チェックは `npx tsc --noEmit`(何も表示されなければ成功)。

### テストが確かめていること
| 区分 | 確かめていること |
|---|---|
| 自己投票 | 自分の動画への票は集計されない / 自己投票しかない動画は順位に出ない |
| 欠席者 | 票が 1 票の動画と 3 票の動画で、合計ではなく平均で順位が決まる |
| not_shown | 放映できなかった動画は、票があっても順位に出ず、他の順位も変わらない |
| 投票なし | 投票が 1 件もない動画は順位に出ない / 票が 0 件なら空の結果 |
| 同点 | 総合点が同じならインパクト平均が高い方が上 / 完全な同点は同順位で次が飛ぶ(1,2,2,4) / 割り切れない平均でも誤差で同点が崩れない |
| 再投票 | 同じ人が同じ動画に投票し直すと新しい内容に上書きされる(順番が逆でも日時が新しい方が残る) |
| 発表段階 | 段階0は空 / 1は3位だけ / 2は3位と2位 / 3は3位・2位・1位 / 隠すべき順位が結果のどこにも含まれない / 同順位や 3 人未満では空の順位になる / 0〜3 以外はエラー |

### 初出の専門用語と一言解説
- **純粋関数**:同じ入力なら必ず同じ結果を返し、外の状態を変えない関数。電卓のようなもの。
- **ユニットテスト(単体テスト)**:小さな部品ひとつひとつを、自動で確かめるテスト。
- **標準競技順位**:同順位が出たら、その人数分だけ次の順位を飛ばす数え方(1,2,2,4)。
- **スクリプト(`scripts`)**:`package.json` に書く、コマンドの短縮名。`npm test` は `vitest run` の短縮。
