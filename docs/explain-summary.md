# ゼミ動画投票システム 説明用1ページ要約(10/22 用)

## 何を作ったか
ゼミ生10名が、互いの自己紹介動画をその場でスマホから評価・投票し、上位3名をすぐ発表するWebシステム。
画面は4つ:投票(/v/…)・管理(/admin)・結果(/result)・QR印刷(/admin/qr)。

## 使った技術と選んだ理由
| 技術 | 一言解説 | 選んだ理由 |
|---|---|---|
| Next.js(App Router) | 画面とサーバー側の窓口を1つのプロジェクトで作れる道具 | 画面とAPIを一緒に作れ、Vercelに載せやすい |
| TypeScript | 型(データの種類)を書ける JavaScript | 取り違えのミスを、動かす前に見つけられる |
| Tailwind CSS | クラス名を並べてデザインする方法 | スマホ優先の見た目を素早く整えられる |
| Supabase(PostgreSQL) | クラウド上のデータベース | 表の形式で保存でき、ルール(制約)をDB自身に守らせられる |
| Vitest | 自動テストの道具 | ルールの正しさを、何度でも自動で検算できる |
| Vercel | 作ったアプリを公開するサービス | 無料枠で足り、Next.jsと相性がよい |
| qrcode | QRコードを作る部品 | 参加者ごとの本人確認URLを配るため |

## 自己投票を防ぐ4つの守り(多重防御)
1. **画面**:自分の動画では投票欄を出さない(親切のための守り)。
2. **API**:自分への投票リクエストを拒否する(不正なリクエスト対策)。
3. **DB**:`CHECK (voter_id <> target_id)` で、保存そのものを拒否する(最後の砦)。
4. **集計**:万一紛れ込んでも、順位計算から除外する。

## 未発表の順位をサーバーが返さない設計
画面で隠すだけだと、ブラウザの開発者ツールで通信を見れば1位が分かってしまう。
そこで、発表段階(0〜3)に応じて、サーバー側が「発表済みの順位だけ」を返事に入れる。
未発表の人の名前は、返事に最初から存在しない。

## 順位の決め方
総合点 = 技術点の平均 + インパクト点の平均(2〜10点)。「合計」でなく「平均」なので、欠席者がいても公平。
同点なら、インパクト平均 → 技術平均の順で比べ、それでも並べば同順位(全員表示)。

## 本物のDBで確認した結果
- 順位計算・投票・管理・結果・QRを含め、自動テスト618件が通過。
- 本物のDBで、テスト投票を入れて確認した。段階0では名前なし、段階1では3位だけ、…と、未発表の名前が返事に出ないことを確認(11項目OK)。確認後は元の状態に戻した。
- 管理APIは、ログインなしだと全7本が401(DBにも触れない)。

## 既知の限界
- ログイン失敗の回数制限は、サーバーのメモリ上にある(再起動で消える)。10人規模の授業では十分と判断。
- 画面の更新は2〜3秒おきのポーリング(リアルタイム通信ではない)。
- 開発用ツール側の依存に、`npm audit` のhigh警告が5件ある(本番に入る部品は0件)。修正は破壊的な古い版への戻しになるため、見送った。
- 動画そのものはアプリで再生しない(教室のスクリーンで流す)。

## 先生の方式との比較
先生の方式:Microsoft Forms で回答を集め、Power Query(Excelのデータ加工機能)で集計し、OneDrive の Excel で順位を出す。

| 観点 | 先生の方式 | 私の方式 |
|---|---|---|
| 本人確認 | 自己申告 | 参加者ごとのQRトークン |
| 即時性 | Excel の「更新」操作が必要 | 投票からほぼリアルタイムで反映 |
| 自己投票の除外 | Power Query で除外 | 画面・API・DBの制約・集計の4か所で防ぐ |
| 動画ごとの制御(投票中・締切・放映不可) | 難しい | 管理画面で切り替えられる |
| 必要なアカウント | Microsoft 365 | Supabase と Vercel(無料枠) |

私の方式の弱み:運営者(管理者)の操作が必要で、通信環境に依存する。
